- **DM15 - sections 1, 2, 4.2, 4.4 and 8: supported original-native demolition-filter verification boundary.** What published interface permits acquiring or constructing an original `cSC4DemolitionOccupantFilter`, identifying it as that owner, establishing its complete per-call inputs, calling all three `cISC4OccupantFilter` predicates, and balancing owned references through city shutdown/save/reload? Section 1 publishes a factory/CLSID for the demolition utility, not the filter; section 2 describes an internal filter pointer, and section 8 exposes no getter (the default-filter setter is a no-op). The SDK publishes the three generic predicate signatures, but not a demolition-filter factory or configuration API. The ABI vtable rows establish slot positions, not acquisition or state-setting permission. Section 4.4 describes passing Phi to an occupant-manager query, so a synchronous borrowed-filter observation may be possible; however, no owner-identification/full-state capture contract is supplied there, and holding a reference would not freeze bounds/privilege/caller/view state. Please also reconcile that query boundary: demolition section 4.4 step 4 names slot 41 with a filter, while occupant-manager section 8.5 calls slot 41 a typed thunk and section 8.4 describes the filter-taking slot 40. A supported callback/proxy route must specify which original calls it observes, the validity/ownership of the filter and other input references, how identical inputs reach independent Rust without private-field access or a second-Rust oracle, and how constructed probes are distinguished from natural calls. Otherwise publish an explicit limitation on which parts of this owner can be verified through existing public interfaces.
